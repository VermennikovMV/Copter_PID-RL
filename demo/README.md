# Демонстрации

Три дрона в одной сцене Gazebo, одновременно и в одном и том же ветре:

| Дрон | Цвет | Управление |
|---|---|---|
| drone1 | синий | штатный ArduPilot (висение — GUIDED, трасса — миссия AUTO) |
| drone2 | оранжевый | ArduPilot + компенсатор возмущений (`RESID_ENABLE=1`) |
| drone3 | фиолетовый | end-to-end нейросеть (команды моторам) |

При висении дроны стоят рядом. На трассе все трое летят одну и ту же трассу один над другим
(через 2 м: ArduPilot сверху, end-to-end снизу), поэтому сразу видно, кто впереди.

```bash
python demo/run.py race      # трасса: 8 пролётных точек (радиус 2,5 м), остановка 2 с (радиус 0,4 м), финиш
python demo/run.py payload   # висение, у всех одновременно отцепляется груз 65 % массы (1,14 кг)
python demo/run.py wind      # висение в сильном ветре: спереди, затишье, справа, затишье
python demo/run.py final     # общий тест: та же трасса, боковые порывы, сброс груза 65 % массы
python demo/run.py race --pass-radius 0.7          # точки нужно проходить точно
python demo/run.py race --waypoint-limits default  # ArduPilot с заводскими ограничениями AUTO
```

ArduPilot и компенсатор летят трассу миссией AUTO; по умолчанию со спортивными ограничениями
(5 м/с, 4 м/с², рывок 5 м/с³), `--waypoint-limits default` — заводские (3 м/с, 2,5 м/с², 1 м/с³).
Радиус пролётных точек одинаков для всех: им же ArduPilot переключает точки (`WP_RADIUS_M`).
Остановка засчитывается, если дрон 2 с простоял в 0,4 м от точки.

По умолчанию открывается окно Gazebo. `--record demo_wind.mp4` вместо окна снимает видео камерой
сцены (в темпе симуляции, с подписями дронов, таймером, скоростью и направлением ветра,
отклонением от точки при висении и временем финиша на трассе).

Что показали записи (одна попытка каждой сцены, Gazebo + SITL):

| Сцена | ArduPilot | Компенсатор | End-to-end |
|---|---|---|---|
| Ветер: среднее отклонение | 17,6 см | **6,6 см** | 10,9 см |
| Груз 65 %: наибольшее отклонение | 22,5 см | 19,5 см | **10,6 см** |
| Трасса, спортивный AUTO: финиш | 24,8 с | 24,9 с | **22,7 с** |
| Трасса, заводской AUTO: финиш | 38,4 с | 38,4 с | **21,4 с** |
| Трасса, точки в радиусе 0,7 м: финиш | **24,9 с** | 25,0 с | 25,2 с |
| Общий тест (порывы, груз 65 %): финиш | 26,0 с | 25,7 с | **24,4 с** |

- Скорость ArduPilot на трассе задаёт планировщик AUTO, а не регулятор: со спортивными
  ограничениями он почти догоняет end-to-end, с заводскими (на плавность) — заметно медленнее.
- Если пролётные точки нужно проходить точно, end-to-end на скорости промахивается и теряет время
  на доворотах.
- Груз 65 % далеко за пределами обучения (до 20 %): после сброса тягу нужно уменьшить примерно
  на 40 %, а поправка тяги ограничена `RESID_THR_MAX` = 15 %, поэтому здесь лучше end-to-end.
  На грузе 20 % (испытания в [docs/results.md](../docs/results.md)) компенсатор с ним вровень.
- Каждая запись проверена: помехи у всех включаются в один шаг симуляции, расписание силы
  одинаковое, старт одинаковый, груз сталкивается только с землёй, ветер требует наклона не больше
  ~30° (предел ArduPilot `ATC_ANGLE_MAX`).

Ветер. Gazebo уже считает сопротивление воздуха Iris при движении относительно земли
(≈ 1,52 Н на м/с), поэтому добавочная сила 1,52·w(t) даёт сопротивление относительно воздуха,
движущегося со скоростью ветра w(t). Каждый порыв ветра: средний ветер + турбулентность (случайные
колебания ~20 % с характерным временем ~2 с, направление в пределах нескольких градусов) + порыв
формы «1 − cos», с плавным нарастанием и спадом. В сцене ветер показывают светлые штрихи, летящие
с его скоростью.

Нужны: собранный [ardupilot-ROSMeetUp](https://github.com/VermennikovMV/ardupilot-ROSMeetUp),
Gazebo Harmonic с `ardupilot_gazebo` и плагин возмущений (см. [docs/setup.md](../docs/setup.md)).
